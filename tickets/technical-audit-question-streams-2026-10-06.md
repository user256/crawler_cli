# Technical-audit implementation streams — 2026-10-06

## Operating model

Three agents own non-overlapping ticket sets. They work in separate worktrees and
may change the question registry only for their assigned question IDs. Each agent
keeps its answerer, detector, fixtures and registry edits together in one change.

The shared result contract is fixed: a check produces retained, run-scoped
evidence and reports Issue, Healthy, Needs validation or Pending. Missing or
partial evidence never becomes Healthy. Agents should not rewrite another
stream's detector, registry entry or fixture to unblock their own work; record
a hand-off instead.

## Streams

| Stream | Agent boundary | Tickets | Start condition |
|---|---|---:|---|
| [A — crawl and HTTP evidence](./technical-audit-stream-a-crawl-http-2026-10-06.md) | Raw crawl, robots, sitemaps, graph, URL families, status and redirects | 38 | Start first |
| [B — page indexability](./technical-audit-stream-b-page-indexability-2026-10-06.md) | Stored HTML, metadata, canonical, hreflang, schema and semantic markup | 35 | Start after A publishes the Q26/Q81 gate interface |
| [C — render, probes and supplied evidence](./technical-audit-stream-c-render-probe-evidence-2026-10-06.md) | Browser/mobile/probe, supplied GSC/manual evidence, exposure, performance and AI policy | 31 | Start after A publishes shared evidence schema; may develop fixtures in parallel |

## Required hand-offs

- **A → B:** Q26 and Q81 are the only run gates. A owns the gate integration
  and must publish the stable gate result before B treats a complete
  stored-HTML population as Healthy.
- **A → B:** sitemap, robots, URL, redirect and response-status evidence is
  consumed by B’s Q9, Q20, Q71, Q73, Q80, Q83, Q87 and Q94 checks.
- **B → C:** Q56 owns the shared `date-consistency` detector. Q60 extends
  its output and must not rebuild it.
- **A → C:** A provides the run and URL identity contract. C supplies
  rendered, active-probe and imported evidence under that identity.
- **C:** Q18, Q31 and Q50 move to `supplied-input` before an answerer can
  run. Q104 remains a documented manual workflow and always stays Pending in
  the automatic runner.
